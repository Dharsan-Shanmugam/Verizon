# Synthetic service-quality augmentation

`36_service_quality_15s_current_event.csv` adds modeled RTT, packet loss, radio
queue delay and explicit TDD/RF scenario indicators for every target-event
cell/timestamp. It is generated by `vdi/service_quality.py` at server startup and
is included in the catalog with a column dictionary.

Version 2 adds explicit synthetic PUSCH SINR, UL BLER, HARQ retransmissions,
receiver interference, handover success, availability/alarms and compute usage.
It also includes a causal transport-jitter proxy from trailing absolute latency
variation, not measured packet-arrival jitter.
RF/coverage impairments alter SINR; error/retransmission scenarios follow it.
A C05 processing-pressure case adds modeled delay/loss. Availability is normal
in this demo, not measured network availability.

Aggregate UL Mbps converts original file-15 MB per 15 seconds using `MB*8/15`.
Synthetic P05 assumes a lognormal distribution inferred from source P50/P10:
`sigma=log(P50/P10)/1.28155`, `P05=P50*exp(-1.64485*sigma)`. It is not measured P05.

## Inputs and provenance

- Original synthetic file 15 / saved replay: current radio utilization.
- Original synthetic file 25: site/shared `latency_ms` and `packet_loss_pct`.
  Transport latency is the maximum of the two supplied link latencies.
  Transport loss combines the two link-loss percentages multiplicatively.
- Cell inventory: n77 cells are eligible for the synthetic TDD scenario.
- Explicit test cases: n77 uplink-slot shortage between -30 and -10 minutes;
  failed neighbor alignment in the final part of that window; a synthetic RF
  impairment on C01 around event start.

## Illustrative response

Let `L` be radio utilization, `G` the positive uplink-demand minus allocated-slot
gap, `T` transport latency, `P` transport loss, and `I` the RF impairment flag.

- Radio queue ms = `0.75 * max(L - 60, 0) + 0.65 * max(G, 0)`.
- Modeled RTT ms = `12 + radio_queue_ms + T + 35 * I + processing_delay`.
- Radio loss % = `0.03 + 0.055 * max(L - 70, 0) + 0.035 * max(G, 0) + 1.5 * I`,
  plus 1% in the explicit high-compute-delay scenario.
- End-to-end loss % = `100 * (1 - (1 - radio_loss/100) * (1 - P/100))`,
  with loss components bounded to 0-100%.

These are transparent simulation formulas, not measurements or a trained
end-to-end service model. They must not be used as evidence of real SLA impact.

## Planning and live use

Page 1 applies the same illustrative radio response to the trained peak-load
forecast and simulator transport estimates. It recommends remedies but takes
no approvals and changes no state.

Page 2 reads the populated CSV and requires three consecutive samples above a
50 ms RTT or 1% loss demo budget before classifying service degradation.
Existing radio and transport safety rules still apply. Counterfactual validation
checks service budgets as well as capacity.

The TDD playbook compares smaller and larger uplink-profile changes. It assumes
10%/20% radio-load reduction, with corresponding 7.5%/15% downlink-utilization
penalties. Residual slot shortage is retained for the smaller change. Steering
compares a limited 10% move with the standard configured fraction. Profiles that
cannot meet service/capacity recovery budgets are blocked before execution.
These assumptions are demonstrator behavior, not calibrated engineering results.

## Regeneration

The generator is deterministic and uses a version plus source size/mtime
fingerprint stored in `artifacts/service_quality_source.json`. It rebuilds the
CSV when those inputs change. Original source CSVs and their provenance are not
rewritten. The added file has its own `data_source` marker and catalog schema.
